# Iudicium S05 integrated folder-to-knowledge qualification

Owner #371, campaign #349; starts from accepted S04 main
`f1be3ce061d91b4e9bfa1c0f1d3bc2b7d1f77998`. This is a qualification contract,
not an attestation of remote acceptance or release delivery.

`scripts/iudicium_journey.py` freezes two public synthetic EN/IT mechanics inputs.
Their canonical input digest is
`6f77ac2a0c1b9ede128a823f8ac2a2457e21695ca5048ef50e44c3ebb7304d4b`.
They are not a representative real evaluation corpus or independently reviewed
labels. No real classification accuracy, calibration or held-out score is computed.
Any future real quality evaluation must freeze its representative corpus, split,
labels, configuration and thresholds before scoring.

The existing CPU qualification composes the same two governed real native EN/IT
calls with actual managed folder enrollment and the existing five-second/two-
observation quiescence. Originals and Versions are captured while AI is Off and a
reviewed processing rule is disabled. Each Source then needs a separate reviewed
rule and three exact reviewed extraction, text representation and Source-scoped
index jobs in the existing scheduler. The representation comes from the actual
extractor; qualification no longer substitutes a hand-materialized text bundle.
Preparing the initially empty global index is an explicit separate operation.
Processing rules never authorize model activation, session enablement, inference
or canonical classification. Existing explicit model/session/task consent remains
required for each native classification request; no extra native call is added.

Actual selected and abstained closed outputs remain distinct. Only a selected
output can enter an independent local CLI destination/rule review, attributable
application, library rebuild, policy revocation and guarded undo. An abstention
records `NOT_APPLICABLE_ABSTENTION`; it is never relabeled to obtain a passing
application. The synthetic test adapter forces both branches in both shells and
inherited default settings so that real abstention cannot leave the selected
branch untested. Scripted reviews exercise the existing permission and atomic
receipt boundary on a disposable public synthetic Instance; they are not human
Windows, usability, accessibility or linguistic observations.

After closing AI, reopen the Instance, pause and observe each Source, resume and
refresh unchanged input, replay the same refresh request and explicitly rebuild
the library and index. Assert no duplicate canonical objects or changed Original/
Version, no lost scheduler/AI receipt or accounting, no implicit inference and no
unreviewed derived job. Strengthen the existing
`iudicium_execution_conformance` gate to require every per-Source and final journey
observation, the frozen input digest and the correct selected/abstained branch.
All existing CPU gates, deadlines, independent WFP/syscall observations, final
integrity audit, cancellation and worker cleanup remain required and unchanged.

`tests/test_iudicium_journey.py` runs the composed services and both test-only
outcomes, inherited Cura, explicit Cura and reversible Current, shared Action
Center pages in all seven shipped catalogs and AI Off on reopen. The complete
native suite also retains S01, processing pause/resume/restart, exact reviewed
application/conflict-safe undo, Cura preference rollback, keyboard/theme/reflow,
catalog and package-resource machine contracts.

Human Windows/UX/accessibility/catalog checks remain `NOT_RUN`/`UNVERIFIED`;
independent label review `NOT_REVIEWED`, real classifier quality `NOT_EVALUATED`,
confidence absent and automatic classification `DENIED`. The omissions were made
nonblocking by the maintainer in #349 comment6186153379. They do not supply runtime
consent, accuracy claims or historical acceptance. Cura #354 stays open until
exact integrated-source qualification. #348 remains independent and unchanged.
