# Emendatio canonical brand qualification

Slice `0.10.1/S04` is owned by [#245](https://github.com/gabned/provelume/issues/245)
under [#198](https://github.com/gabned/provelume/issues/198). Package identity remains
`0.10.0` until the separate release-preparation PR. This document defines the
checks; successful source tests alone do not certify a released artifact.

## Source and packaged identity

`assets/windows/provelume.svg` is the existing first-party public Provelume mark:
navy `#0B1F3A`, blue `#1769E0`, gold `#F6C453`. It is the sole editable source.
`scripts/generate_windows_icon.py` accepts its bounded explicit SVG subset and
fails on unsupported elements, transforms, external resources or styling. Fixed
cubic subdivision and supersampling produce sizes 16, 20, 24, 32, 40, 48, 64, 128
and 256. Stored DEFLATE blocks make PNG serialization independent of compressor
versions. Actual independent rebuild equivalence remains a required observation.

Run the generator to update derivatives; run it with `--check` to compare every
generated byte, including both manifests. The manifest binds source SHA-256 and
each derived asset's SHA-256 and size. `core/provelume/static/brand/` ships in the
wheel and frozen package, serving local Browser/favicon/About and native shell
surfaces. It contains generated copies, never a second editable design.
The compatibility `--output` option checks or creates only a requested ICO.

The shell prefers its packaged icon over legacy fallback paths. Executable,
installer, uninstaller and shortcuts retain their existing AppUserModelID and
identity. `verify_windows_brand.ps1` maps PE files as data without executing them,
then compares all nine resource frames with the canonical ICO. Build and installed
shell smoke fail if a different or incomplete mark is embedded. The installed
smoke also compares Windows-associated icon pixels with the canonical icon,
detecting a different displayed cached/resource result without flushing the
user's global icon cache. Shortcut/Start-menu identity and native tray lifecycle
checks remain required; no new tray behavior is introduced.

## Appearance and accessibility

Browser marks are decorative local images; the visible localized Provelume name,
tagline, navigation and About text remain authoritative. The native title keeps
its product text alongside the PNG. Transparent exterior pixels surround an
opaque navy tile, so the same mark applies in light and dark modes without
recoloring or remote assets. Forced-colors mode keeps the textual label and focus
contract; a decorative brand image does not encode state or replace text.

Automatic checks cover source propagation, stale/missing derivatives, wheel
identity, resource frames, native association, EN/IT semantics and existing layout
probes. Actual subjective appearance must still be observed on the prepared exact
build: executable/window, setup/uninstall, shortcut/Start menu/taskbar, About and
existing tray, at normal and high scaling in applicable light/dark/high-contrast
modes. Record OS, scale, mode and artifact/head with the observation. An earlier
visual deferral cannot certify the changed brand; missing material evidence is
reported as pending, never PASS. Do not expand Windows support through a hosted
runner result or silently reset shell/theme settings for a test.

For the `0.10.1` preview, the release owner explicitly directed publication with
this material observation deferred until after publication. The deferral is a
known qualification limitation, not a successful observation: automated resource,
pixel, layout and lifecycle checks remain PASS only within their stated scopes.
The prepared exact-build instructions remain available for the later observation,
whose result must be recorded independently without rewriting release history.

## Upgrade and integrated matrix

The existing permanent installer test now defaults to the immutable public
`0.10.0` installer and matching wheel at tag commit
`72099ac35d2430c0de221fc9bfaca88942c9e883`. The approved older baselines remain.
Size/hash checks precede execution. The real baseline creates synthetic canonical
knowledge; upgrade preserves the complete Instance fingerprint and launcher
settings. Startup, reinstall, uninstall, backup/restore and the existing explicit
rollback boundary remain required. No automatic downgrade or updater is added.

S04 qualification retains full Ruff/pytest and every applicable permanent Ubuntu
and Windows workflow, deterministic distributions, release dry run, SBOM/provenance,
offline verification, clean-room and resource checks. Integrated regressions cover
S01 Source/network/UNC failure states, S02 exclusions across preview/watch/reconcile/
reindex/transfer, and S03 bounded read-only Google/privacy/offline behavior. Actual
Google observations may be reused only with original timestamps and verified
unchanged semantic dependencies; no new consent or provider content operation is
implied by a brand change. Any affected evidence must be requalified.

Executable and setup remain unsigned development/preview artifacts. Signing,
notarization and independent publisher authentication remain `0.21.0`; descriptive
metadata and matching hashes cannot claim them. Publication follows the distinct
release-preparation and permanent release gates only after all slices qualify.
