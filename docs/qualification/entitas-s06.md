## Integrated preservation journeys

`tests/test_entitas_integrated_qualification.py` joins the already accepted
contracts and separately tests their composition. All inputs and model responses
are synthetic. External socket connections and DNS attempts are denied in these
journeys; native loopback/event-loop wakeups remain available on Windows.

- Eight manual journeys cover schema 1 and 2, both portable derived-state choices
  and Cura/default or explicitly selected Current. Each deeply preflights and
  explicitly migrates a populated Instance, verifies its pre-migration backup,
  retains existing Project/Collection identities, creates an evidence-bound Claim,
  Task and version-pinned Relation, rejects a stale write without side effects,
  changes the source Document Version, and follows the retained old Original.
  A later canonical edit is retained in the verified rollback backup before
  explicit restore. Export/import preserves canonical bytes, Originals, immutable
  history and retained preferences. The shared interface reads the recovered
  object, escapes hostile-looking text, and preserves the external launcher's
  actual interface selection, language/appearance and preference file bytes.
- Two AI-bearing schema-2 journeys retain existing producer configuration/state
  across explicit migration, create an actual governed synthetic producer job and
  immutable receipt, grant manual Source-scoped review separately, disable AI,
  approve once, and retain history after draft/base-result disposal, a later manual
  edit and Document Version change. Backup/restore and both portable choices retain
  canonical/review/immutable scheduler receipt bytes and accounting. The existing
  replacement contract deliberately increments the execution generation, keeps AI
  Off and marks the retained job restored; it does not rewrite accounting or
  silently replay inference. Foreign AI-bearing import is refused with verified
  target rollback. Stale Relation endpoints stay explicit, without retargeting.

An `include` export requires a ready index and Markdown library. The journeys first
observe its refusal without Instance mutation, then explicitly rebuild those
disposable projections. `rebuild` never pretends to have exported ready projections.
Lifecycle lock files are transient coordination, while the new migration receipt
is the expected additive authoritative record. Neither is confused with an
unexpected change to retained AI policy, consent or receipt bytes.

These journeys complement the S01 hostile closed-record cases; S02 real process
death, old-binary refusal and native filesystem access profiles; S03 concurrent
manual writers/exact Evidence; S04 guarded API/browser forms; and S05 producer
attribution, revoked authority, atomic interruption and explicit review cases.
They do not replace their complete unchanged native suites or original reports.
