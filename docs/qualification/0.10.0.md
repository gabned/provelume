## Perceptio support perimeter

- Universal representation: the 14-profile registry preserves the eight Lectio compatibility
  rows and adds only the six selected Perceptio profiles. Preserve, Inspect, Extract, Preview,
  Local enrich and unavailable AI enrich remain independent.
- Photo: bounded JPEG, PNG, TIFF and BMP inspection; optional Pillow 12.3.0 sanitized preview on
  the qualified Ubuntu cell. GPS/device values stay excluded by default. WebP, HEIC/HEIF, AVIF
  and RAW/DNG remain Preserve-only.
- Audio: bounded local inspection for the admitted containers; deterministic WAV/PCM16 evidence;
  optional operator-supplied whisper.cpp 1.9.2 and exact multilingual tiny `q5_1` model. No engine,
  model or decoder is bundled or downloaded.
- Video: bounded MP4, MOV, MKV, WebM and AVI inspection with the closed codec matrix; external
  FFmpeg/ffprobe 9.0.1 decoding is qualified only on Ubuntu 24.04 x86-64. Windows is absent-safe.
- Additional file families: exactly UTF-8 CSV cells, XLSX sheets/cached cells and ZIP member
  metadata over Python 3.12 standard-library parsers. Active content never executes and ZIP
  members are not extracted to the host.
- Integrated pilot: service, CLI, GET-only API and accessible EN/IT Browser share one offline,
  read-only model with exact anchors, uncertainty, reversible correction annotations, component
  evidence and explicit degraded/unavailable/recovery states.

## Recovery and migration

The immutable N-1 baseline is `v0.9.0` at
`e08125a8600f9c4300d0d173613a03f8bbc31327`. Qualification covers clean install, N-1 upgrade,
remove/rebuild equivalence, verified backup/restore, portable transfer, reinstall and uninstall.
Rollback never silently downgrades schemas: install an immutable compatible predecessor and open
only a proved-compatible Instance or restore its matching verified backup into a separate path.
Uninstall removes program files, shortcuts and registration while preserving launcher settings and
every Instance unless the user performs a separate explicit deletion.

## Windows signing truth

The executable, installer and uninstaller are published only as explicitly unsigned artifacts.
`Get-AuthenticodeSignature` must report the expected unsigned state during qualification.
Descriptive `Neobeta` and version metadata do not authenticate a Publisher or resolve `Unknown
publisher`; the Windows dialog may still report `Unknown publisher`, and signed-release
verification remains fail-closed.

## Release-bundle verification

The permanent release pipeline builds twice from the exact merge commit and requires byte-identical
wheel and sdist output. It assembles `release-manifest.json`, CycloneDX SBOM, `SHA256SUMS`, input
locks, deterministic/rebuild/offline evidence, release assurance, Windows evidence and both
offline verifiers. Publication may use only that bundle. After GitHub publication, every public
asset is downloaded again and checked for exact bytes, size, SHA-256, version, tag, commit,
embedded identity and the declared unsigned boundary.

Exact candidate head, merge commit, workflow run/job IDs, artifact digests, findings and public
redownload results belong in owner PR #185, issue #183 and tracker #160. Those live GitHub
records are authoritative over this static contract.
