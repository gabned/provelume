## Windows signing truth

The executable, installer and uninstaller are published only as explicitly unsigned artifacts.
`Get-AuthenticodeSignature` must report the expected unsigned state during qualification, while the
signed-release verifier remains fail-closed. `Neobeta`, file-version and Add/Remove Programs
metadata are descriptive only. They do not authenticate the Publisher and do not resolve
`Unknown publisher`.

## Qualified and unqualified component perimeter

- OCR: Ubuntu 24.04 x86-64, CPython 3.12, local Tesseract 5.x with explicitly installed `eng`,
  pypdfium2 5.13.0/PDFium 153.0.7999.0 and Pillow 12.3.0 for the documented PDF/TIFF/PNG/JPEG/BMP
  fixtures. Other combinations, including Windows OCR, are unqualified.
- Email: EML on Ubuntu 24.04 and Windows Server 2025 x86-64 with CPython 3.12; Maildir only on
  Ubuntu 24.04 x86-64. Mbox and every other matrix combination are unsupported or unqualified.
- Google: deterministic synthetic Gmail/Drive conformance only. No credential or authenticated
  real-provider qualification is present.
- Transcript: explicit local SRT/WebVTT UTF-8 profiles on Ubuntu 24.04 and Windows Server 2025
  x86-64 with CPython 3.12. Audio/video, ASR, diarization, cloud import and proprietary formats are
  outside the release.
- Cross-source findings: deterministic synthetic provider-neutral findings and reversible human
  decisions only; no automatic merge, entity resolution, canonical mutation or provider write-back.

## Release-bundle verification

The permanent release pipeline builds twice on independent runners from the exact merge commit and
requires byte-identical wheel and sdist output. It then assembles `release-manifest.json`, the
CycloneDX SBOM, `SHA256SUMS`, build-input locks, deterministic/rebuild/offline evidence,
`release-assurance.json`, Windows package evidence and the offline verifier. Publication may use
only that bundle. After GitHub publication, every public asset must be downloaded again and checked
for exact bytes, SHA-256, version, tag, commit, embedded identity and the declared unsigned boundary.

The exact candidate head, merge commit, run/job IDs, artifact checksums, findings and public
redownload results belong in PR #PENDING, issue #158 and tracker #137. Those live GitHub records are
authoritative over this static contract.
