# Verify installation

Provelume can inspect the installed Python package without using the network or reading Instance knowledge.

## What is verified

For normal wheel installations, Provelume first requires the selected distribution to resolve to the package tree supplying the running verifier. It validates the local metadata root and files before reading a bounded UTF-8 `Name`, PEP 440 `Version` or `direct_url.json`, streams PEP 376 `RECORD` under fixed row and line limits, checks relevant package/distribution files against their recorded size and SHA-256 under a cumulative hashing-byte budget, and scans the installed `provelume/` package directory incrementally for unexpected regular files and unsafe symbolic links or filesystem reparse points.

The check reports one of three states:

- `package_integrity_verified` — all relevant hashed package bytes match and no unexpected package files are present;
- `modified_installation` — one or more installed package files are missing, changed, unreadable, unsafe or unexpected;
- `verification_unavailable` — the installation is editable, lacks usable wheel metadata or cannot be inspected completely and safely.

## What is not claimed

A matching wheel `RECORD` does not prove that the wheel was published by Provelume. An unofficial wheel can include matching metadata for its own files.

For this reason, the API and UI always expose official origin separately. The first implementation reports:

```text
origin.status = not_established
```

A future trusted local release manifest or provider-independent signature may establish origin without replacing the byte-integrity check.

## CLI

```bash
provelume verify-installation
```

The command prints the same JSON contract used by the API.

Exit codes:

- `0` — package integrity verified;
- `2` — modified installation;
- `3` — verification unavailable.

The command performs no writes.

## API

```http
GET /api/v1/security/installation
```

Example shape:

```json
{
  "schema_version": 1,
  "status": "package_integrity_verified",
  "package": {
    "distribution": "provelume",
    "version": "0.2.0",
    "editable": false
  },
  "integrity": {
    "verified": true,
    "checked_files": 42,
    "tracked_files": 42,
    "unhashed_files": 0,
    "unexpected_files": 0
  },
  "origin": {
    "status": "not_established",
    "detail": "..."
  },
  "network_used": false,
  "reason": "...",
  "findings": [],
  "findings_truncated": false
}
```

## Browser

Open `/security/installation`. The page is available in English and Italian and explains integrity and origin as separate concepts.

## Scope exclusions

The first check does not verify:

- Python interpreter/base-environment files;
- generated bytecode in standard `__pycache__` paths;
- console entrypoint scripts outside package scope;
- installed runtime dependencies against the release SBOM;
- future Windows installer signatures or container layers;
- Instance data, configuration, plugins or personal files.

These exclusions prevent local mutable state from being confused with the reusable public Core package.
