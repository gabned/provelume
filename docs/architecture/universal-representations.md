# Universal representations and effective support

This developer contract describes the additive `0.10/S01` foundation. It implements no photo,
audio, video or AI capability and does not change the published `0.9.0` package identity.

## Authority and identity

An Original and its canonical DocumentVersion remain the authority. A representation is derived,
attributable, removable and rebuildable. Its stable ID is the SHA-256 identity of:

1. the exact Version ID and Original SHA-256;
2. the recipe ID, version and canonical settings fingerprint;
3. the ordered output descriptors and their SHA-256/size fingerprint.

Creation time, lifecycle state and storage location do not silently change this content identity.
A different recipe or different output has a different representation ID. `previous` and `parent`
relations preserve derivation history rather than replacing an older result.

`representation_bundle.schema.json` is the public JSON Schema; the public domain enums live in
`provelume.representations`. Runtime validation is strict and rejects unknown or incomplete
fields. Each bundle records component and adapter versions, settings, closed warning codes,
output media type/path/hash/size, lifecycle, availability, provenance, corrections, anchors,
safety limits and immutable-authority invariants. Available bundles have no blocker; degraded or
unavailable bundles carry one closed reason and may identify the missing component.

## Independent support operations

`representation-support-registry.schema.json` validates the packaged versioned registry. It
contains one row for every profile and every operation:

- `preserve`: retain exact bytes and identity;
- `inspect`: read bounded structural facts;
- `extract`: derive content such as normalized text;
- `preview`: present an inert derived view;
- `local_enrich`: run an explicitly installed local component;
- `ai_enrich`: reserved and unavailable with `not_implemented` in S01.

`declared_state` is `supported`, `optional` or `unsupported`. `effective_state` is `available`,
`degraded` or `unavailable`. A degraded/unavailable row has one closed reason and may name the
missing component. An available row has neither. Preserve never implies another row or search
indexing.

The OCR rows are resolved from current local configuration and component evidence without a
network request. Disabled OCR reports `disabled_by_configuration`; a missing local engine,
renderer or language pack reports the exact missing component. All other S01 rows use packaged
first-party declarations.

## Anchors and corrections

Every anchor repeats the exact Version and representation IDs. Page anchors contain a positive
page number. Time anchors contain ordered non-negative millisecond bounds. Region anchors contain
a page and positive rectangle. `slide` and `symbol` remain reserved and carry only an explicit
reservation. S06 additively activates closed target-v1 shapes for `sheet`, CSV/XLSX `cell` and ZIP
`member`; the prior explicit reservation remains valid so existing schema-v1 bundles need no
migration. A typed target is valid only for its declared profile and exact coordinates/path/hash.

Corrections reference an anchor, bind before/after checksums and are always reversible. They are
annotations on a derived representation, never a mutation of the Original, a canonical record or
provider data.

## Lifecycle, paths and limits

Native bundles and outputs stay below
`state/derived/representations/<representation-id>/`. Paths must be relative, normalized,
Windows-safe, case-distinct and free of file/directory collisions. The v1 ceiling is 1,000 outputs,
100,000 anchors, 10,000 corrections, 1,000 warnings, 16 GiB per output, 512 GiB total and a 1,000x
expansion ratio. A bundle may choose lower limits but never higher ones.

Paths must also be NFC-normalized, and every selected lower path/segment ceiling is enforced by
runtime validation. Deep validation resolves each bundle's Version and Original back to canonical
records and rechecks the authoritative Original bytes before accepting derived state.

Removal deletes only the native output tree after writing a derived removal receipt. Rebuild
accepts regenerated bytes only when every hash/size and the complete active bundle fingerprint
match the receipt. Failure removes the partial rebuild and leaves Original/canonical/provider
state untouched.

## Lectio compatibility view

`lectio-representation-compatibility.json` maps, without conversion:

- document extraction and document bundles;
- local OCR document bundles;
- local email intake;
- Google Gmail/Drive read-only evidence;
- SRT and WebVTT transcript revisions;
- cross-source qualification findings.

The view reports the existing profile, locations and visible record count. It neither rewrites
those files nor pretends that a legacy bundle is a native S01 bundle. Schema-2 Instances remain
readable with no eager migration and no `.md` sidecar beside an Original.

## One read model and portable behavior

`RepresentationReadModel` supplies the same keys to the application service,
`representation-support`/`representations` CLI commands, `/api/v1/representations*`, and the
EN/IT `/representations` Browser page. Every result records `network_used: false` and
`mutated: false`.

Backups already include durable `state/derived` artifacts. Portable export in both rebuild and
include modes preserves `state_artifacts: include`; restore/import invokes deep Instance
validation before commit. `representation_state_findings` makes a malformed bundle, unsafe
location, missing output, checksum/size mismatch or altered removal receipt invalidate the staged
Instance.
