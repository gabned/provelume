# Deterministic Markdown library and safe Viewer

Status: active Unreleased product contract for `0.6/S03` under issue #95. Package and embedded
release identity remain `0.5.1`; this implementation slice does not create a tag or release.

## Authority boundary

Canonical JSON under `knowledge/` and content-addressed acquired bytes under `originals/` remain
authoritative. `library/` is derived state. It can be removed and rebuilt, is excluded from local
backups, and is never read as canonical input. Editing generated Markdown changes only the
projection; a deliberate acquisition through the normal ingestion/review path is required before
edited bytes can become a new Original or DocumentVersion.

A rebuild starts and ends with deep Instance validation. The bound canonical fingerprint covers
canonical records and retained Original bytes. A changed or invalid fingerprint prevents success;
the report states `canonical_mutation: none` and records that neither network nor AI capability was
used.

## Projection layout

The staged projection has this deterministic shape:

```text
library/
  .provelume-library.json
  README.md
  areas/
    README.md
    <Area/Subarea slugs>/
      README.md
      <primary Document>.md
  projects/
    README.md
    <Area/Project ancestry slugs>/
      README.md
      <primary Document>.md
  archive/
    README.md
  unclassified/
    README.md
    <unclassified Document>.md
  views/
    README.md
    collections/
    tags/
    people/
    sources/
    dates/
    types/
```

Area, Project and Collection directories use the stable slugs derived by the canonical hierarchy.
Source, media-type and Document path components use an ASCII lowercase readable base plus a
128-bit suffix derived from the stable identity. Components contain no Windows-reserved path
characters, have deterministic case and remain collision-safe when labels are equal. Date views
use `YYYY/MM/DD`; invalid dates fail into a deterministic `unknown` index rather than becoming a
path.

Every Document has exactly one generated Markdown file: its current primary Area, Project or
Collection directory, or `unclassified/` when no primary classification exists. Secondary
associations appear only as relative links in the corresponding README index. Source, date and
media-type views also link to that one primary file. Collection views are populated from canonical
classifications. Tag and person roots are present but empty because Instance schema 2 has no
canonical tag/person assignment record; the projection does not infer or invent them.

All links generated by Provelume are POSIX-style relative links. A projected Document links to the
one content-addressed Original outside `library/`; it does not copy Original bytes. Authored links
inside an acquired Markdown body remain authored content rather than generated routing.

## Document representations

For acquired UTF-8 Markdown, the generated file adds explicit derived front matter and then retains
the authored Markdown body. The exact bytes remain separately preserved and downloadable as the
Original. Other supported formats use the current hash-validated deterministic document bundle;
missing bundles are reconstructed locally from the verified Original. Generated bundle asset links
are rewritten to portable relative references rather than copied into another authoritative store.

Every generated Document front matter records projection schema, Document/Version/Source identity,
primary and secondary hierarchy identities and Original SHA-256. It explicitly declares that the
projection is not canonical.

## Manifest, validation and replacement

`.provelume-library.json` contains the generator/schema identity, deep canonical fingerprint,
sorted path/size/SHA-256 entries, one unique primary path per canonical Document and a deterministic
content fingerprint. It contains no generation timestamp, host path or machine identity, so equal
canonical input produces byte-identical output on repeated rebuilds.

`library-status` validates the bounded manifest, exact file inventory, regular-file/symlink
boundary, file sizes and hashes, primary-path identity and current canonical fingerprint. It returns
`missing`, `invalid`, `modified`, `stale` or `ready` without creating projection state.

Construction happens in a `.library-building-*` directory inside the Instance's backup-excluded
lock/staging area on the same filesystem. Only a complete validated tree is swapped into
`library/`. When a previous projection exists it is moved into that same transient area first; a
failed staged or post-commit validation restores it before the operation returns an error. The
exclusive `derived-rebuild` lock serializes standalone and coordinated projection rebuilds. File,
Document, character and manifest bounds fail visibly rather than publishing a partial tree.
The operational default is 1,000 Documents; an explicit local override is honored up to the
50,000-Document absolute guardrail, with the independent file-count limit still enforced.

Local commands and application-service methods are:

```text
provelume library-rebuild INSTANCE [--max-documents N]
provelume library-status INSTANCE
ProvelumeInstance.rebuild_library(...)
ProvelumeInstance.library_status()
```

The existing `rebuild-derived --mode incremental|full|agreement` now commits and fingerprints the
library after bundles, the search index and duplicate evidence. Agreement requires the incremental
and full snapshots to include the same validated library fingerprint.

## Safe built-in Viewer

The loopback Viewer exposes four explicit choices:

- **Rendered**: a bounded local structural Markdown subset;
- **Raw Markdown**: escaped Markdown representation;
- **Original text**: escaped exact decoded text when the Original is UTF-8 text;
- **Download Original**: attachment delivery of the exact preserved bytes after current
  Version/Original hash and size verification.

The renderer emits only Provelume-owned heading, paragraph, list, blockquote, emphasis and code
markup. Raw HTML is escaped. Markdown links and images become inert labels: no document-controlled
`href`, `src`, iframe, object, script, style, media or form element is emitted. Binary Originals are
never inlined as active same-origin content. The existing restrictive CSP, `nosniff`, local Host
check and private-cache headers remain defense in depth.

Read-only HTTP surfaces are:

```text
GET /api/v1/library
GET /api/v1/documents/{document-id}/content?mode=raw|original
GET /api/v1/documents/{document-id}/original
/documents/{document-id}?mode=rendered|raw|original
```

HTTP has no projection rebuild or write-back method. Reading the Viewer never builds a bundle,
creates `library/`, contacts a service or accepts a generated projection as knowledge.

## Slice boundary

Archive, remove-from-library, recoverable trash and authorized permanent purge remain `0.6/S04`.
Portable export/import, hostile bundle validation and Windows/Linux transfer qualification remain
`0.6/S05`. This slice introduces no autonomous tagging/classification, connector, OCR, AI,
semantic search, cloud storage or general Markdown editor.
