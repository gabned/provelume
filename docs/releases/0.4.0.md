# Provelume Core 0.4.0 release plan

This plan delivers one bounded product release through issue #57 and its single owner product
pull request. The implementation and separate release-preparation step are complete. This
document does not itself create a tag or publish a release.

Package and embedded identity are aligned at `0.4.0`. The official tag and public artifacts
remain restricted to the permanent release workflow operating on the reviewed `main` result.

## Product contract

The release provides the first per-user Windows x64 installer with a bundled Python runtime and
a small native launcher. Runtime files live below the per-user application directory. Launcher
settings and downloaded updates live below local application state. The selected portable
Instance lives outside both and is never an uninstall target.

The launcher may create or open an Instance, start and stop the loopback-only Provelume server,
open the Knowledge Browser, show installed identity and check for updates. About and ordinary
product use remain offline. A manual check, or a startup check explicitly enabled by the user,
contacts GitHub Releases through the first transport adapter and sends no Instance content.

Each release publishes `provelume-windows-update.json` beside the installer. The launcher matches
version, tag, channel, commit, platform, architecture, installer name and size, then verifies the
downloaded installer SHA-256 before offering to run it. The user must confirm both network access
and installer execution.

## Trust boundary

The first installer is an unsigned preview. Hash agreement with metadata obtained through the
same HTTPS release transport detects corruption or inconsistency but does not independently
authenticate the publisher. Authenticode, detached provider-independent signing, unattended
application, runtime slots, Instance backup/migration, rollback and interrupted-update recovery
remain later work and must not be implied by this release.

## Supported target

- Windows 10 22H2 (build 19045) or Windows 11;
- x86-64 processor/runtime only;
- per-user installation without administrator rights;
- one launcher process and one loopback-only server process;
- EN/IT launcher and Knowledge Browser surfaces.

The installer may display a Windows SmartScreen warning because it is not yet code-signed.

## Release gates

1. all existing Core, clean-room, deterministic-build and Linux/Windows tests remain green;
2. update selection, malformed metadata, channel, downgrade, unsafe URL and checksum tests pass
   against synthetic fixtures without live network access;
3. the frozen executable writes offline diagnostics containing the exact installed build identity;
4. Windows CI installs the generated setup into a clean per-user target, bootstraps an Instance,
   uninstalls the runtime and proves that the separate Instance remains readable;
5. official publication includes the installer and update manifest in `release-manifest.json`,
   `SHA256SUMS`, attestations and GitHub Release assets without weakening the Python release gate.
