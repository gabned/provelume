## Use the integrated journey

1. Open Cura, the primary interface for new and inherited settings. An explicit
   Current backup selection stays preserved. Switch through the existing browser
   or launcher/local-panel settings and return to Cura using the same controls.
2. Register a local folder. Exact Originals and Versions can be captured, read and
   searched with AI Off. Existing Instance, Knowledge, preferences, credentials,
   jobs and independent AI/network permissions remain with their existing owners.
3. Review derived-work rules separately. Disabled, proposals, confirmation per job
   and explicitly controlled automatic work remain distinct. The current automatic
   allowlist is bounded extraction, local text representation and scoped index
   refresh. Use existing maintenance controls for pause, resume, cancellation and
   recovery; these rules never grant permission to infer or classify.
4. For classification, use the existing optional model setup and explicit model,
   session and task consent. Preview one exact current Version and current possible
   destinations, then inspect the receipt-bound proposal in the Action Center.
   The observed native execution scope is EN/IT on the existing local profile.
   Configured-provider contracts remain available; untested live external providers
   receive no new qualification claim.
5. Review the source and choose destinations independently before manual
   application. Rules bound Source/prefix, targets, language, expiry and impact.
   The application receipt supports guarded undo while the current classification
   still matches its postimage. Remedial undo needs no retained private model body
   or new inference. Abstention stays explicit; proposals can be discarded while
   their existing receipts and accounting remain attributable.
6. Reopening and rebuilding the disposable library/index preserve Originals,
   canonical Versions, receipts and accounting. AI is Off after restart; uncertain
   work is not silently replayed. Optional OCR, transcription, media and synthesis
   retain their own component/resource/privacy/consent controls.

## Qualification and limits

The [final qualification contract](../qualification/0.13.0.md) requires all native,
cross-platform, independent network/resource, installed, container, source identity,
review, merge, post-merge and official distribution checks on the final source.
The existing two real native classification calls are composed with actual managed
folder capture and independently reviewed extraction/representation/index jobs;
both selected and abstained application branches also have synthetic conformance.

**Real classifier quality is NOT_EVALUATED, confidence is unavailable and automatic
classification is DENIED.** Synthetic fixtures and successful execution demonstrate
mechanics, not representative real accuracy or calibrated confidence. No real
classification score is computed here. Any later evaluation must freeze its
representative corpus, calibration/held-out split, labels/configuration and
thresholds before scoring. Confidence alone never grants permission.

Human Windows/UX/accessibility/catalog observations remain **NOT_RUN / UNVERIFIED**;
independent classifier labels **NOT_REVIEWED**. The maintainer made these omissions
nonblocking in [#349 comment6186153379](https://github.com/gabned/provelume/issues/349#issuecomment-6186153379).
No historical screen-reader or linguistic attestation is promoted. Real CPU results
describe their observed hosts; minimum-laptop hardware remains NOT_RUN. Windows
remains explicitly unsigned, with the corresponding operating-system publisher
warnings; signing is not inferred from hashes, metadata or runtime receipts.

## Install and verify

Use the matching complete `provelume-0.13.0-installation-kit.zip` only after actual
public readiness is observed. Follow the existing
[installation procedure](../publication-installation.md) and
[offline verification/provenance procedure](../release-verification.md).
Verify the exact version/tag/reviewed-main commit, complete asset inventory,
checksums, SBOM, manifest, independent rebuild, public-workflow provenance, receipt,
outer kit and readiness marker. Raw payloads require the matching publication
receipt import to constitute a metadata-complete installation; source/build/install
time is not substituted for an actual publication observation.

Upgrade the existing Instance using the ready exact-version kit and existing
installation controls. Preserve its location and explicit interface selection.
Weights remain outside application and portable Instance artifacts. License
acceptance, self-test/activation and session/task consent remain explicit; an
upgrade, page visit, processing rule or confidence value never enables AI.
