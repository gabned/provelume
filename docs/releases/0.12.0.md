## Product outcome and boundaries

AI off is the initial supported mode. Deterministic capture, preservation, extraction,
search and reading continue without a model, external account or network. The
qualified Local Recommended setup explicitly installs one CPU-first package, loads it
on demand and works offline; installation/update traffic is separate from inference.
An external provider or ordered hybrid fallback requires deliberate configuration.
The first useful action is manual synthesis/key points for one exact Document Version,
with removable derived output and evidence anchors, never canonical classification.

The Custodia subset of [#224](https://github.com/gabned/provelume/issues/224) comprises
the Recommended local profile, governed registry, verified install/update/rollback,
Advanced compatible BYOM, optional BYO provider through the same gateway, and explicit
Off/Local/External/Hybrid controls. S01 selected no model. The evaluated approximately
0.5–1.5B direction did not establish adequate quality; the final recommendation is the
qualified Qwen3.5-2B Q5_K_M profile for extractive summary/key points in EN/IT. Classification,
destination proposals and calibrated confidence remain 0.13; global capture and advanced
network/tray work, including [#259](https://github.com/gabned/provelume/issues/259), remain
0.20. Release numbers 0.13 onward do not change.

Base receipts, template identities, adversarial isolation and adapter conformance belong
in Custodia before user inference. Iudicium extends these foundations with classification,
confidence calibration and reversible controlled application receipts; it will not create
a second gateway or policy resolver.

## S01 executable contract

S07 setup implementation is described in the [surface contract](../architecture/ai-setup-previews.md),
[user guide](../ai-privacy-guide.md) and [qualification matrix](../qualification/custodia-s07-setup.md).

The [gateway contract](../architecture/ai-gateway-preflight.md) defines the internal
service seam and trust boundary. It reads no Instance, Original, endpoint or credential.
One pure resolver intersects Instance, every Source/data category and every Area/Project
association/ancestor restriction. Explicit deny, AI off and local-only ceilings survive
more specific preferences. Missing, conflicting, unknown or unqualified inputs fail closed.
An allowed plan is neither consent nor dispatch authority. The test-only adapter is absent
from the product package and cannot produce a real-execution receipt.

The focused executable demonstration is:

```text
.venv/Scripts/python.exe -m pytest -q tests/test_ai_gateway.py::test_executable_s01_demonstration
```

Use `.venv/bin/python` on POSIX. Native qualification also runs the complete repository
Ruff and pytest commands, `git diff --check`, the accepted Protocol/effect/ownership gates,
complete exact-head Linux/Windows CI and review/thread inventory. Required post-merge CI
and actual-main verification preceded completion of #312 through #313. #311 remains open.

## Release-wide qualification and separate release workstream

Privacy-safe receipts distinguish planning, denial, simulation, attempts and real execution.
No private prompt/output, local path or credential enters ordinary diagnostics or public
evidence. A loopback URL, provider brand or compatible API never proves offline inference.
No document or model output can obtain tools, secrets, more context or canonical authority.
Budgets, context/version, route, policy, template and consent must be revalidated before
dispatch, retry and fallback through the S06 execution boundary.

S09 must provide real local-runtime evidence; fake responses cannot qualify a real model.
Hardware/task/language thresholds are fixed before scoring. External live smoke requires
separate bounded authorization and synthetic content; an untested profile is not qualified.
Reuse Cura's Action Center, scheduler, design system and seven offline UI catalogs.
No new service, paid laboratory, connector, RAG or network/tray work enters this train.

After all nine slices, a separate release-preparation owner aligns package/runtime/embedded/
Windows identity and runs release-chain checks on the unchanged candidate. Only separately
authorized official preview publication may create the tag and artifacts. S01 performs no
version change, tag, publication, installer change or historical receipt rewrite.
