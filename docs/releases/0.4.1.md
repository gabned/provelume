# Provelume Core 0.4.1 release plan

This plan closes the patch-only Windows Product Shell hardening executed through issue #62 and its
single owner product pull request. The implementation and separate release-preparation step are
complete. This document does not itself create a tag or publish a release.

```text
RELEASE_PLAN_SCHEMA: 1
PLANNED_VERSION: 0.4.1
MILESTONE_TITLE: 0.4.1
CURRENT_PACKAGE_VERSION: 0.4.1
PACKAGE_VERSION_UPDATE: APPLIED
EXECUTION_ISSUE: 62
PRODUCT_THEME: WINDOWS_PRODUCT_SHELL_HARDENING
RELEASE_STATUS: PUBLISHED_PREVIEW
WINDOWS_SIGNING: NOT_INCLUDED
UPDATE_APPLY_MODE: USER_CONFIRMED_INSTALLER
```

Package and embedded identity are aligned at `0.4.1`. The official tag and public artifacts remain
restricted to the permanent release workflow operating on the reviewed `main` result.

## Patch contract

This release adds no ingestion, knowledge-management or connector capability. It corrects
reproducible `0.4.0` shell failures and improves only the related layout, localization, state and
error handling. The portable Instance schema, stable Windows AppId, per-user installation path and
explicit update policy remain unchanged.

The corrected behaviors are:

- a moved or deleted selected Instance is reported without silently creating a replacement, while
  Choose and Create remain available for recovery;
- the browser opens only after the current loopback backend is ready, and startup or later process
  failures retain an actionable state;
- the console-free frozen launcher starts Uvicorn without depending on unavailable console streams;
- update metadata must bind its advertised commit to the commit resolved from the release tag;
- reduced work areas and Windows scaling use a scrollable launcher layout with explicit DPI
  awareness and control states aligned to backend and update activity.

## Release evidence

The permanent Windows release pipeline downloads the immutable public `0.4.0` installer and checks
its recorded size and SHA-256 before using it as the upgrade baseline. It creates only a synthetic
Instance and synthetic launcher settings, installs the `0.4.1` candidate over the same AppId and
target, verifies the new frozen identity and loopback backend, then proves that Instance and
settings bytes remain unchanged after uninstall.

Automated evidence also covers default and Unicode paths, shortcuts, one product registration,
reinstall/uninstall, bundled Python isolation from installed Git or Python, the reviewed Windows
dependency lock, EN/IT Tk layout probes at 100%, 125%, 150% and 200% modeled DPI, update error and
stale-result handling, the full Core suite on Ubuntu and Windows, clean-room checks, deterministic
Python output, an independently provisioned offline rebuild and release-bundle verification.

Hosted Windows runners do not prove physical Windows 10 22H2 or Windows 11 client editions, a real
standard-user desktop session, subjective visual quality, or human shortcut interaction beyond
installation metadata and target validation. Those results remain explicitly blocked or manual;
the release makes no stronger claim.

## Trust and update boundary

The installer remains an unsigned preview. SHA-256 and release metadata provide consistency
evidence but not independent publisher authentication. Update checks require explicit network
policy, send no Instance content, never downgrade, and never execute an installer automatically or
silently. Authenticode, runtime slots, automatic rollback, transactional recovery and Instance
migrations remain outside this patch.

The `0.5.0` roadmap entry remains the next forecast and is not activated by this release.
