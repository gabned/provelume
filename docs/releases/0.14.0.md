## Upgrade and recover

Use the matching complete `provelume-0.14.0-installation-kit.zip` only after its
actual public readiness marker has been observed. Follow the existing
[installation procedure](../publication-installation.md) and
[offline verification/provenance procedure](../release-verification.md).
Verify version/tag/reviewed-main commit, complete inventory, hashes, SBOM/notices,
manifest, independent rebuild, workflow provenance, receipt, outer kit and marker.
Raw payloads need the matching receipt import for a metadata-complete installation.

Stop every older runtime before migrating an existing Instance. Read-only
`provelume validate INSTANCE` verifies retained canonical references and Original
bytes and identifies supported older schemas. `provelume migrate INSTANCE`
performs the explicit forward migration through schema 3 after deep preflight and
an independently re-read/hash-verified backup. Record the returned backup path
and digest. A package install, ordinary launch or Instance selection supplies no
implicit migration consent. Windows' packaged operator commands and the complete
recovery procedure are in the
[portable Instance contract](../architecture/portable-instance.md).

Migration adds object heads/history for existing Projects/Collections while
retaining their IDs, hierarchy records and acquired Original bytes. It preserves
preferences, consents, permissions and retained state within the documented native
filesystem perimeter. Unknown/future schemas, invalid legacy records or unavailable
required native access-control evidence stop the operation explicitly.

Older binaries refuse schema 3. Reverting uses the verified pre-migration backup,
with the supported restore procedure retaining a verified backup of later changes;
there is no in-place schema downgrade. Interrupted migration/restore uses its
bound lifecycle recovery evidence. Keep every runtime stopped while replacing an
Instance and follow the operator's reported recovery action.

Backup/restore and portable transfer retain canonical objects, immutable history,
Originals, reviewed provenance and supported preferences. Choose portable
`include` only with ready index/library projections; `rebuild` explicitly omits
those disposable projections. AI-bearing replacement retains its existing
same-Instance accounting boundary. A refused foreign AI-bearing import restores
the verified target backup; it does not grant new producer or review authority.

## Use attributable knowledge

1. Open Cura, the primary interface. An explicit Current backup selection remains
   preserved and reversible through the existing browser/launcher/local-panel
   settings. Capture, read and manually organize knowledge with AI Off.
2. Open a document Version and choose **Create an object from this version**, or
   **Choose an exact source version** from Knowledge objects. Choose Entity,
   Claim, Decision, Task, Outcome, Calendar event or Commitment, fill its typed
   fields, select sources and explicitly confirm the operation. A Claim needs a
   source. Aliases do not merge identities. Existing Project/Collection creation,
   names and parents keep their hierarchy controls and stable identities.
3. Inspect evidence availability and immutable revisions. Concurrent edits cannot
   overwrite a stale preimage. Relations retain exact endpoint revisions; advancing
   an endpoint requires the explicit refresh choice. A newer Document Version does
   not retarget old Evidence. Missing/purged bytes remain unavailable, and available
   bytes never certify an assertion's factual truth. Original downloads are inert
   attachments within their documented size limit.
4. Enter explicit-offset Task/Commitment dates and Calendar event endpoints with a
   matching supported IANA zone. Dates, types and endpoints are user choices;
   recurrence, all-day inference and provider calendar synchronization are absent.
5. For an existing governed summary/key-points result, choose **Prepare draft**.
   Select and inspect the typed fields. Preparing it starts no inference. Inspect
   the attributable result and exact source, then use the separate manual review
   capability, preview and final confirmation. AI/model consent and canonical
   review permission remain independent; a valid existing proposal can be reviewed
   with AI Off. Automatic application is forbidden for this domain.
6. Reopening, explicit projection rebuild, backup/restore and portable round trips
   retain authoritative knowledge, old-Version attribution, immutable receipts and
   accounting. Disposing derived proposals/results does not erase an accepted
   canonical object or rewrite its retained provenance. AI stays Off after restart.

The [manual interface](../architecture/knowledge-object-interface.md),
[services](../architecture/knowledge-object-services.md) and
[proposal/review contract](../architecture/knowledge-object-review.md) describe
bounds, history, withdrawal and stale-authority behavior. The local preview HTTP
API is first-party and bounded; it is not the later stabilized API/MCP product.

installed, container, migration/recovery, original-byte and distribution evidence.
