## Product outcome

`0.5.0` turns the original filesystem vertical slice into a durable, observable and recoverable
local intake subsystem while preserving exact Originals and provider-independent canonical
knowledge.

The release delivers:

- schema-versioned ingestion runs and item attempts with `pending`, `running`, `completed` and
  `failed` states;
- per-item failure isolation, bounded errors and explicit retry of only failed or interrupted
  items;
- crash-safe reconciliation after partial Original, Version, Document or extraction writes;
- a local Drop Inbox with copy-by-default behavior and optional move-after-verified-commit;
- configurable Inbox display name, Drop folder and managed-copy folder;
- relative Instance-local paths or absolute folders elsewhere on the local filesystem;
- a navigable, path-redacted operation log across CLI, read-only API and EN/IT browser;
- deterministic version-addressed document bundles containing normalized Markdown, page maps and
  bounded assets;
- exact and conservative probable-duplicate evidence with no automatic merge or deletion;
- read-only Original assurance covering hashes, sizes, storage references and canonical links;
- an exclusive Instance rebuild lock plus incremental, full and agreement rebuild modes for
  bundles, full-text search and duplicate evidence.

## Filesystem and portability boundary

The selected Drop and managed-copy folders may live outside the Instance when the local process has
access. Missing external locations fail visibly and are not silently recreated. Drop and managed
folders must be separate and may not overlap the Instance root, canonical Originals, knowledge,
state, indexes or retained submission evidence.

Canonical Originals, readable knowledge JSON, derived state, indexes, operation records,
submissions and assurance/rebuild reports remain inside the Instance. Backing up only the Instance
therefore preserves acquired knowledge but does not preserve unacquired files waiting in an
external Drop folder.

The Inbox display name and Drop folder may change after use. Relocating an already-used managed-copy
folder is blocked until a separate verified relocation workflow can preserve every Source binding,
working copy and crash-recovery boundary.

## Assurance boundary

An acquired Original is never overwritten or deleted by routine ingestion, retry, bundle/index
rebuild, duplicate analysis, Source disappearance or folder-setting changes. Exact duplicate bytes
may share one content-addressed Original while every Document, locator and Acquisition remains
separate. Probable duplicates are review evidence only. Original assurance reports findings and
performs no repair.

The operation log records ordered events, status, metrics and related canonical identities. It does
not persist credentials or physical external paths. Browser and API mutation remains closed except
for the loopback-only, CSRF-protected folder-settings form; the public settings API is read-only and
redacts external absolute paths.

## Release evidence

The reviewed release candidate must pass:

- Ruff and the full test suite on Ubuntu and Windows;
- clean-room and repository-hygiene checks;
- deterministic wheel and source-distribution comparison across independently provisioned builds;
- release-bundle verification, checksums, CycloneDX SBOM and provenance attestations;
- Windows x64 installer build, install, real upgrade from the immutable public `0.4.1` installer,
  embedded identity, loopback startup, Unicode/default paths, Instance preservation and uninstall;
- exact tag, package, public commit and release-channel agreement.

The preview installer remains unsigned. SHA-256, manifest and GitHub attestation evidence do not
replace independent publisher authentication. Update checks remain explicit, send no Instance
content, never apply a downgrade and require user confirmation before installer handoff.

## Explicit exclusions

This release does not include OCR, a background filesystem watcher, generic scheduling, network
Sources, AI classification, semantic/vector search, automatic duplicate merge, automatic repair,
external canonical storage, managed-folder migration, Authenticode, unattended update application,
runtime slots or automatic rollback.

`0.6.0` remains the next non-activated forecast for portable Instance lifecycle and the
hierarchical Markdown library.
