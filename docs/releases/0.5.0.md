## Outcome

The `0.5.0` implementation lane makes local intake durable, observable and recoverable while
preserving exact Originals and keeping derived state reproducible. Five bounded owner slices are
required before release preparation:

- `0.5/S01` — persistent ingestion run/item ledger, isolated failure and explicit retry;
- `0.5/S02` — local Drop Inbox, move-after-verified-commit and navigable operation log;
- `0.5/S03` — version-addressed Markdown, page-map and bounded-asset document bundles;
- `0.5/S04` — exact/probable duplicate evidence and read-only Original assurance;
- `0.5/S05` — exclusive rebuild lock, incremental/full agreement, scale limits and final
  implementation evidence.

## Release gate

A later release-preparation change may align package and embedded identity to `0.5.0` only after:

- all five slices are merged to one reconciled `main` baseline;
- exact-head CI, Windows preview install/uninstall and deterministic-build evidence are green;
- no owner product PR or unresolved review thread remains;
- a final agreement rebuild proves identical normalized incremental/full derived state without
  changing canonical knowledge;
- issue #66 records the merged slice and implementation checkpoint.

That later change owns package version, dated changelog heading, release notes, tag, installer and
publication. This plan does not authorize any of those actions and leaves the latest published
preview at `v0.4.1`.
