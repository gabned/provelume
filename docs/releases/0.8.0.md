# Provelume Core 0.8.0 — Vigilia release record

`Vigilia` is the first Provelume preview with durable, explicitly configured scheduling for
folder Sources and safe local maintenance. It makes refresh, reconciliation, reindex recovery and
resource observations visible without turning installation or startup into authority to run them.

This remains a **prerelease**. No policy is created or enabled by upgrade, and scheduled work runs
only while the current local runtime is active. Native filesystem-event watchers, an always-on
desktop agent, unattended updates, OCR, email/Google intake, AI and RAG remain later work.

## What 0.8.0 enables

- Define strict manual, bounded interval or local-calendar policies with explicit IANA timezone,
  daylight-saving, quiet-window, jitter, missed-run and retry behavior.
- Persist jobs, leases, heartbeats, checkpoints, attempts and immutable terminal receipts so an
  interruption has an explainable resume, restart or manual-intervention outcome.
- Register independently enabled or paused local, removable and already-mounted network folder
  Sources with recursive scope, include/exclude patterns, temporary-file rejection, quiescence and
  visible mount-loss recovery.
- Run idempotent `source.refresh` work without treating duplicate observations or unchanged bytes
  as new canonical Versions or Acquisitions.
- Inspect the closed safe-local maintenance catalogue and run its available full/incremental FTS,
  library rebuild, Source reconciliation, Instance validation, Original assurance and duplicate
  actions. Backup entries remain visibly unschedulable until an explicit target is supplied through
  the separately authorized backup workflow.
- Reconcile one exact folder Source against current canonical evidence with content-free cursors
  and closed active, paused, missing, error, superseded or reauthorization-required lifecycle
  states.
- Observe path- and content-free Instance file, logical-byte and category totals plus filesystem
  capacity, trends and optional warning/critical thresholds without cleanup or quota enforcement.
- Inspect and control the same contracts through local service and CLI surfaces, path-redacted
  read-only API endpoints and semantically aligned English/Italian Browser views.
- Preserve scheduler, folder Source, maintenance, reconciliation and resource evidence through
  deep validation, backup/restore and portable export/import.

## Authority and default-disabled behavior

Creating or opening an Instance creates no scheduler policy, job or maintenance run. An upgrade
does not enable folder refresh, provider access, update checks, repair, deletion, purge, retention
or resource cleanup. Policies require an explicit local action, remain independently
enabled/paused/disabled and cannot grant more authority than their exact Instance and Source
scope.

A `network` folder Source is a path already mounted by the operating system. Provelume does not
discover shares, negotiate SMB/NFS, obtain credentials or open an alternate transport. Source
reconciliation remains read-only; resource thresholds record evidence only. No timer authorizes
repair, purge, retention deletion, destination cleanup or provider-side change.

Canonical readable JSON and immutable Originals remain authoritative. Indexes, Markdown-library
files, caches, views and reindex generations remain derived and rebuildable. Rename, missing-mount
and retry evidence never silently deletes or rewrites acquired knowledge.

## Deliberately not included

`0.8.0` does not include a native filesystem-event watcher, always-on Windows or macOS agent,
unattended updater, Authenticode or macOS signing, OCR, email or Google intake, Action Center,
mobile capture, semantic/vector search, AI classification, RAG, MCP, Git/rsync synchronization,
Synology deployment, Provelume Cloud, accounts or billing. It does not activate `0.9.0 Lectio`.

The Windows updater remains user-controlled: checks are disabled by default, downloading requires
an explicit action and applying an update requires confirmation through the normal unsigned
installer. The product remains local-first and usable without GitHub at runtime, Provelume Cloud,
Nexus or an external AI provider.
