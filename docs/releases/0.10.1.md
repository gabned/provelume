## Release outcome

The campaign was initialized under Protocol 1.4.1/schema 2. Its immutable history
continues to validate through `tools/agent_protocol_v1_4_1.py`; the current
repository protocol and operational gates are read from `AGENTS.md`. Historical
receipts are never relabelled as evidence for a newer protocol.

Emendatio corrects four concrete onboarding and identity problems without pulling later roadmap work forward:

1. reliable enrollment and diagnostics for local, removable, mounted-network and explicitly qualified Windows UNC Folder Sources;
2. visible, versioned per-Source exclusions with safe defaults and an ingestion preview;
3. a guided ordinary-user `Connect Google` flow for separately consented read-only Gmail and Drive;
4. one canonical first-party Provelume brand source propagated deterministically across the existing Core/Windows surfaces, followed by integrated qualification.

Package, runtime, embedded and Windows identity are aligned to `0.10.1` by the distinct release-preparation owner PR after S01–S04 reached verified `MERGED` state.

## Ordered bounded slices

### `0.10.1/S01 — Source enrollment and Windows network-path qualification`

Provide one EN/IT Folder Source enrollment contract for local folders, removable storage, already-mounted network volumes and explicitly qualified Windows UNC paths. Validate before enrollment, expose actionable mount/reachability/permission/Windows-session/mapped-drive/unsupported-path diagnostics, and preserve stable Source identity through reconnect/reconciliation. Qualify synthetic and real Windows network-path cases where permanent infrastructure permits.

Issue #210 and OWNER PR #211 completed this slice at verified squash merge
`26dee0fd74b43d39e46afe0e5a258130849ee97c`, after exact-head qualification and all 11
post-merge permanent workflows succeeded. Native PR_MERGED receipt
`2a3576f2939bfc066a4428c01f1f4f1b1b9ae2aa306b428b0c6529b555497762` is retained
in #198. The implementation and regression matrix are described in
[`durable-folder-sources.md`](../architecture/durable-folder-sources.md).

Out of scope: network/share discovery, internal SMB/NFS clients, share credential storage, firewall or LAN-binding changes, and background network-volume recovery.

### `0.10.1/S02 — Per-Source exclusions, safe defaults and ingestion preview`

Add visible, versioned, editable and disableable exclusions for subfolders, exact files, extensions/types and bounded portable globs. The visible default profile ignores at least `.git/**`, `.github/**`, `.gitignore`, `.gitattributes` and `.gitmodules`. Preview counts and reasons before application; support explicit override, deterministic serialization, traversal safety, bounded pattern complexity, scan/watch/reconciliation/reindex parity, backup/export/import and explainable ignore diagnostics.

### `0.10.1/S03 — Guided read-only Google connection journey`

Deliver the ordinary `Connect Google` path for separately consented read-only Gmail and Drive using the current installed-app OAuth/PKCE contract, least-privilege scopes, connection test and connected/expired/revoked/reconnect state. Initial backfill is bounded and continuation/cancellation/retry/revoke are safe. Windows-hosted and Browser surfaces share Source identity and read model. Tokens and unnecessary identifiers never enter canonical state, logs, diagnostics, backup/export or portable transfer.

## Release-wide qualification boundary

Before release preparation, the train must prove the bounded local/removable/network/UNC matrix and failure states; duplicate Source prevention and restart/recovery; exclusion preview and scan/watch/reconcile/reindex behavior; authenticated Google connect/reconnect/revoke/cancel/backfill/privacy/read-only/offline behavior; clean install plus real upgrade from published `0.10.0`, uninstall/rollback and automated Windows brand resource/pixel/layout/lifecycle checks; Ruff, full pytest, permanent Ubuntu/Windows matrices, accessibility, EN/IT semantic parity, security/privacy, deterministic build/rebuild, SBOM/provenance, clean-room guarantees, backup/restore, portable transfer, offline verification and resource bounds.

The release owner directed the `0.10.1` preview to retain S04 while deferring the
material native Windows appearance observation until after publication. This is
recorded as `DEFERRED`, never `PASS`; the release notes and qualification evidence
must preserve that limitation. Publication does not certify unobserved setup,
window, Start, taskbar, About, tray, scaling or applicable appearance-mode quality.

Every real finding receives a regression or the affected capability is narrowed. Gates are never weakened to admit a feature.

## Explicit deferrals

Emendatio does not include Action Center, advanced queue/tray UX, menu redesign or #167 click-outside behavior, system-locale preference redesign, reset settings, Lucide/general UI icon-framework rollout, AI/RAG/embeddings/classification/autonomy controls, cloud OCR or remote AI fallback, new providers, Google writes/Calendar, complete background agent, NAS/self-hosting expansion, signing, automatic updater, or other `0.11.0`+ features. Lucide remains a later `0.11/S07` concern and #167 remains future-roadmap evidence.
