# Provelume Core 0.10.0 — Perceptio development plan

`Perceptio` is the active, unpublished development plan for portable photo, audio, video and
selected additional-file representations plus a truthful inventory of the components, models and
licenses that produce them. It starts from the published `0.9.0 — Lectio` provenance, ingestion,
OCR, email, Google-read-only, transcript, finding and Windows-shell contracts. Exact Originals
remain authoritative; every new representation remains attributable, removable and rebuildable.

Planning remains active. S01 was delivered by owner PR #163 for issue #162 and S02 by owner PR
#168 for issue #166. S03 is the one active implementation slice under issue #169 and owner PR
#170. It adds only the bounded photo profile; it does not implement audio/video, change package/
runtime identity, create a tag/release, publish an asset, download a runtime/model or make
Perceptio available. S04–S07 remain planned. GitHub remains authoritative for issue, pull-request
and merge state.

## Canonical outcome and user promise

Perceptio lets a user preserve common media and understand what Provelume can truthfully do with
each exact Version: preserve it, inspect it, extract from it, preview it, enrich it locally or leave
an unsupported operation visibly unavailable. Supported representations carry page, time and
region anchors so a search result or correction can reopen the exact evidence instead of pointing
only to an opaque transcript or media file.

The second user promise is inspectability: a non-technical EN/IT catalogue explains which
component, model, codec or host prerequisite is installed or required, which version and license
apply, how it reached the runtime and whether update/security information was actually checked.
Observation never applies an update.

Perceptio is suitable for a personal multimedia-archive pilot only after verified publication and
only inside its published format, model, codec, platform, performance and privacy matrix. It is not
the coherent daily-use or controlled public-beta gate; that remains `0.11.0 — Cura`.

## Stable release boundaries

- Originals, canonical records and provider data are never changed by identification, extraction,
  preview, local enrichment, component inspection, correction or rebuild.
- A preserved format is not automatically extractable, previewable or searchable. The support
  registry records the effective level, implementation, limits and reason for any unavailable
  operation.
- Representations live in checksum-bound versioned bundles and carry the exact recipe,
  component/model identity, settings, warnings and evidence anchors needed for deterministic
  validation and rebuild.
- No `.md` sidecar is created beside a source file by default. Markdown stays inside derived
  bundles and the rebuildable library projection unless a later explicit export contract says
  otherwise.
- Local metadata and deterministic extraction remain useful with ASR, QR/barcode and every other
  optional model/engine disabled.
- Disabled/offline operation performs no catalogue, advisory, provider, model or runtime network
  request. A check and an update are always separate actions; this release never downloads or
  upgrades a component merely because a newer version exists.
- Unsupported, encrypted, corrupt, excessive or hostile input remains preserved when safe and
  fails the requested higher-level operation within explicit count, byte, expansion, pixel,
  duration, memory, disk, process and time bounds.

## Ordered bounded slices

Every slice starts as `planned`. A slice becomes active only after the preceding slice is closed
and a just-in-time issue plus exactly one owner PRODUCT pull request bind its exact scope and head.
No operational issue exists for any slice at activation time.

### 0.10/S01 — Universal representation and support-registry contract

- **User problem:** current document, OCR, email and transcript bundles expose related ideas
  through profile-specific contracts, so future media support could become inconsistent or imply
  capabilities that are not actually available.
- **Verifiable result:** one versioned universal representation-bundle and support-registry
  contract models Preserve, Inspect, Extract, Preview, Local enrich and AI enrich independently;
  it defines page/time/region and reserved slide/sheet/cell/member/symbol anchors, recipes,
  warnings, correction annotations, lifecycle and exact capability reasons. Existing document,
  OCR, email and transcript evidence is mapped through compatibility fixtures without rewriting
  stored state.
- **Dependencies:** published Lectio bundle/provenance contracts, immutable Originals, portable
  Instance validation, derived-state rebuild and `0.8.0` durable jobs.
- **Surfaces:** public schemas and domain types, support registry, derived-bundle validation,
  read-only service/CLI/API/Browser inspection, backup/export/import rules, architecture and EN/IT
  developer/user documentation, synthetic conformance fixtures.
- **Explicit boundaries:** no photo/audio/video parser, decoder, preview, ASR, OCR change, model,
  native dependency, migration rewrite, provider call or AI path; `AI enrich` is a declared
  unavailable support level, not an implementation.
- **Minimum qualification:** schema round trips and negative fixtures; stable identity and path
  traversal/collision limits; existing bundle compatibility; remove/rebuild validation; anchors
  resolve only inside the exact Version/representation; backup/portable-transfer/deep-validation
  coverage; disabled/offline no-network proof on Ubuntu and Windows CI.
- **Primary risk:** promoting derived or engine-specific fields into canonical identity, or
  presenting preservation as extraction/preview support.
- **Compatibility and migration:** additive schema/contracts only. Existing schema-2 Instances and
  Lectio bundles remain readable and byte-unchanged; no eager migration or new canonical field is
  required.
- **Windows and packaging:** pure first-party contract code and fixtures; no installer payload,
  native binary, model, version metadata or update-channel change.
- **Completion criteria:** the registry is closed and versioned; all six support levels and
  unavailable reasons are testable; legacy profiles pass compatibility fixtures; all public
  surfaces use the same read model; docs and threat-model delta agree; required candidate and
  trusted-base workflows pass on one unchanged head.
- **Delivered state:** completed by merge of owner PR #163 for #162 from
  `product/0.10-s01-universal-representation-contract`; no later slice was activated.

### 0.10/S02 — Installed and release component inventory with EN/IT catalogue

- **User problem:** users cannot yet see one complete, truthful view of Python packages, native
  tools, codecs, models, language packs and host prerequisites or distinguish installed,
  approved, latest-known, missing and unsupported state.
- **Verifiable result:** a versioned component record and machine-readable export reconcile
  installed metadata, checked-in native/model manifests and release SBOM evidence; the EN/IT
  catalogue explains category, purpose, effective/approved/latest-known versions, origin, hashes
  or PURL, license/notices, dependency relation, platform, update route, last-check evidence and
  closed status.
- **Dependencies:** S01 registry/evidence vocabulary, existing build identity, release manifest,
  CycloneDX and external-component evidence.
- **Surfaces:** component inventory service, CLI, read-only API and Browser catalogue; development
  and release manifests; EN/IT user/operator docs; optional manual/scheduled read-only catalogue
  and OSV-format check behind explicit network policy.
- **Explicit boundaries:** no `pip`, package-manager, binary, model or language-pack install;
  no automatic remediation; no ambient discovery traffic; no `latest` claim without a successful
  dated source check; no credentials, private paths or Instance content in inventory/export.
- **Minimum qualification:** installed-versus-release reconciliation; missing/ahead/pinned/EOL/
  unverified/security-action fixtures; offline and stale-evidence states; dependency/license
  completeness; path/secret redaction; bounded allowlisted checks, retry and cache expiry if the
  network-check sub-capability passes its entry gate; EN/IT/accessibility parity on Ubuntu and
  Windows.
- **Primary risk:** a partial inventory or stale upstream observation being presented as complete,
  current or safe.
- **Compatibility and migration:** inventory/check results are additive, derived and removable;
  they do not alter canonical knowledge or require an Instance migration. Schema evolution is
  versioned and older clients receive an explicit compatibility state.
- **Windows and packaging:** catalogue must distinguish bundled, installer-provided,
  host-provided and absent components. The base installer stays usable without optional media
  engines/models; no publisher, signing or automatic-update claim changes.
- **Completion criteria:** every effective release/runtime component class is either inventoried
  or explicitly reported as unavailable/unverified; release SBOM comparison is deterministic;
  offline never checks; a check never updates; EN/IT UI/export/docs agree; security/licensing and
  candidate/trusted-base workflows pass.
- **Delivered state:** completed by merge of owner PR #168 for #166 from
  `product/0.10-s02-component-inventory`; package and publication identity remain unchanged.

### 0.10/S03 — Photo metadata, privacy, duplicate proposals and OCR profiles

- **User problem:** photo/image Originals can be preserved or OCRed only through document-oriented
  paths, without a coherent metadata/preview/privacy contract or trustworthy distinction between
  exact and perceptual similarity.
- **Verifiable result:** bounded photo profiles create a universal representation with dimensions,
  orientation/color evidence, safe preview, EXIF/IPTC/XMP and capture-time observations, explicit
  GPS precision/redaction state, separate exact/perceptual duplicate evidence, page/region OCR
  reuse and separately typed QR/barcode observations when a qualified adapter is present.
- **Dependencies:** S01 bundle/anchor registry, S02 component evidence and the Lectio OCR contract.
- **Surfaces:** local file identification and jobs, photo representation/preview, gallery-ready
  read model, metadata and privacy controls, duplicate/finding evidence, service/CLI/API/Browser,
  backup/export/import, EN/IT docs and format matrix.
- **Explicit boundaries:** JPEG/PNG/TIFF/BMP are the baseline candidates; selected WebP may enter
  only with a locked qualified decoder. HEIC/HEIF/AVIF and RAW/DNG default to Preserve/Inspect or
  embedded-preview unless activation-time evidence proves more. No ambient photo-library scan,
  face/identity/emotion/sensitive-trait inference, metadata write-back, source edit, GPS sharing by
  default, automatic duplicate merge or deletion.
- **Minimum qualification:** orientation/color and malformed-metadata fixtures; metadata size/
  nesting/pixel/decompression limits; GPS default-redaction/export checks; exact versus perceptual
  collision and false-positive fixtures; OCR anchor reuse; preview active-content isolation;
  realistic camera/export samples with sanitized public provenance; Ubuntu/Windows matrix.
- **Primary risk:** leaking sensitive location/device metadata or turning a similarity score into
  identity/deletion authority.
- **Compatibility and migration:** adds derived photo bundles and observations only; existing OCR
  bundles stay valid. Reprocessing uses a new recipe/output fingerprint and never rewrites an
  Original or old result.
- **Windows and packaging:** every Pillow/ExifTool/ZXing or alternative choice requires an exact
  activation ADR, license/notice, version/hash and distribution decision. Missing optional tools
  degrade visibly; the core installer remains functional without them and downloads none.
- **Completion criteria:** the exact release profile matrix is closed; privacy defaults and
  unsupported states are proven; representations remove/rebuild deterministically; realistic and
  hostile fixtures, EN/IT UX/docs, accessibility, backup/restore and all exact-head gates pass.
- **Active state:** issue #169 and owner PR #170 on
  `product/0.10-s03-photo-profiles`; package and publication identity remain unchanged.

### 0.10/S04 — Local audio transcription and time anchors

- **User problem:** audio Originals cannot yet produce a local, citable transcript with explicit
  codec/model/settings provenance and honest uncertainty.
- **Verifiable result:** bounded supported audio profiles expose container/codec/track/chapter/
  duration inspection, waveform/energy preview data and optional local-ASR transcript bundles with
  segment and qualified word timestamps, confidence/warnings and `time-map.json` links to exact
  evidence.
- **Dependencies:** S01 representation/time-anchor contract, S02 component/model inventory and the
  Lectio transcript/correction contracts.
- **Surfaces:** audio identification/decoding and durable jobs, replaceable ASR adapter, model
  manifest, transcript/waveform representation, player-ready read model, correction annotations,
  service/CLI/API/Browser, EN/IT docs and qualification matrix.
- **Explicit boundaries:** candidate containers are WAV, FLAC, MP3, M4A/AAC, OGG and Opus, but
  each codec/platform cell remains unavailable until qualified. Local execution only; no remote
  speech service, model download, summary, classification, speaker identity or provider write.
  Diarization is not a baseline completion requirement and may be admitted only by a later explicit
  model/license/consent decision as uncertain speaker proposals.
- **Minimum qualification:** corrupt/truncated/oversized/duration/channel and unsupported-codec
  fixtures; deterministic decode/resample recipe; language/model/device/quantization settings;
  timestamp/citation reopening; cancellation/checkpoint/retry/cleanup; empty/silent/low-confidence
  audio; representative speech/music/noise samples; bounded CPU/GPU/memory/disk/time behavior;
  no-network proof.
- **Primary risk:** nondeterministic model/codec behavior being presented as verified transcript,
  participant identity or precisely reproducible text.
- **Compatibility and migration:** additive derived bundles/jobs/annotations; no canonical schema
  rewrite. Re-running with another model creates a distinct representation and preserves prior
  evidence/corrections.
- **Windows and packaging:** faster-whisper/CTranslate2 and whisper.cpp remain alternatives until
  the slice selects and locks a qualified path. Models/codecs are explicit optional components,
  never silently bundled or downloaded; missing capability is truthful in the installer/runtime.
- **Completion criteria:** one closed local audio/ASR matrix and replaceable adapter pass realistic
  plus hostile fixtures; exact time citations, uncertainty, correction, removal/rebuild,
  cancellation/recovery, EN/IT UX/docs, licensing/privacy and exact-head workflows all pass.
- **Initial state:** `planned`; no issue or owner PR.

### 0.10/S05 — Video streams, subtitles, scenes, keyframes and frame OCR

- **User problem:** video Originals cannot yet be inspected or searched through bounded streams,
  subtitles, audio, scenes and frames while retaining exact time/region provenance.
- **Verifiable result:** qualified video profiles inspect container/streams/codecs/duration/
  chapters, preserve embedded subtitles, reuse S04 local audio transcription, create deterministic
  bounded scene/keyframe evidence and apply the Lectio OCR contract only to explicitly selected
  frames, with combined time/region anchors.
- **Dependencies:** S01 bundles/anchors, S02 inventory, S03 image/region behavior, S04 audio/time

- **Surfaces:** video inspection/decoding and jobs, subtitle/transcript/scene/keyframe/frame-OCR
  representations, player-ready read model, service/CLI/API/Browser, backup/export/import, EN/IT
  docs and codec/platform matrix.
- **Explicit boundaries:** MP4/MOV/MKV/WebM/AVI are candidates, not blanket codec support. No live
  camera/microphone/feed, surveillance, generative media, remote inference, DRM bypass, continuous

  Preserve/Inspect with the higher operation unavailable.
- **Minimum qualification:** container/stream/subtitle timestamp fixtures; unsupported/encrypted/

## Release-wide exit criteria

Perceptio cannot enter a separate release-preparation workstream until all of the following are
true on `main`:

1. S01–S07 are completed in order through closed just-in-time ownership, and no operational slice
   or unresolved technical finding remains.
2. The shipped support matrix names every qualified format/container/codec/model/platform cell and
   every Preserve/Inspect-only or unavailable operation without treating forecast examples as
   delivered support.
3. Removing all Perceptio representations and indexes and rebuilding from exact Originals plus
   recorded recipes yields equivalent manifested outputs without canonical/provider mutation.
4. Page, time and region citations plus correction annotations reopen the exact evidence and
   preserve machine uncertainty and prior derivation history.
5. Corrupt, hostile, unsupported and excessive inputs fail inside declared resource/process bounds;
   every optional native/model dependency is absent-safe and explicitly inventoried.
6. Disabled/offline operation performs no provider, catalogue, advisory, model or runtime traffic;
   no component/model is downloaded or updated implicitly.
7. GPS and other sensitive metadata remain excluded from default exports, notifications,
   diagnostics and support bundles; active content never executes.
8. The installed/runtime catalogue agrees with manifests, notices, licenses, model records and
   release SBOM evidence, including truthful stale/not-checked/update-known states.
9. EN/IT UX, accessibility, user/operator/developer documentation, realistic-data qualification,
   security/privacy abuse cases, performance/resource budgets, backup/restore, portable transfer,
   clean install, N-1 upgrade, rollback and uninstall evidence pass for the declared perimeter.
10. The personal multimedia-pilot and controlled-tester limits are documented. Perceptio remains
    unavailable until a later exact-version PR, tag pipeline and canonical release-bundle
    publication complete independently.
