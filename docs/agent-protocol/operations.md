# Native Protocol operations

The accepted pin in `.github/agent-protocol/pin.json` selects the same immutable
Protocol source for CLI and Work. Read the canonical topic contract and the local
documents selected for the actual phase, host and workstream. A byte digest proves
integrity, never authority. The repository's PRODUCT policy, required native tests,
review governance and production consent remain local.

## Optional Lifecycle v2 activation

Lifecycle v2 activation is optional and currently deferred by the maintainer.
The independent engine stays adopted and verified; its installation does not
activate a signed journal. Existing and new workstreams may use the accepted PR-local legacy procedure in `docs/agent-development-v1.4.9.md` and its verified historical document selection; no global checkpoint is introduced.

Operator enrollment, signing setup, WSL and paid laboratory provisioning are not
prerequisites for that native route. Native tests, source integrity, policy-before-
binding, ownership, exact-head CI, complete reviews/threads and production consent
remain mandatory as applicable. A PR description or digest never grants authority.

Each workstream retains one authoritative state and its actual route in the handoff.
Starting v2 requires explicit activation and independently approved host enrollment.
Once a signed journal exists, preserve identity/history and use its typed recovery
and closure; do not fall back after a failed or uncertain operation. Migration of
an existing owner requires a separate supported coordinated operation. No manual
checkpoint edits, new capabilities or reinterpretation of historical receipts.

Report v2 activation and real signed-journal recovery as DEFERRED_BY_MAINTAINER,
never PASS. This deferral does not block ordinary native PRODUCT work and does not
certify v2 migration or replace any required native acceptance.

## Independent engine and optional v2 operations

Run `python tools/agent_protocol_v2.py verify` before importing the dependency.
Select documentation with `python tools/agent_protocol_v2.py documents --phase
START --host CLI --workstream PROTOCOL`; use the actual context rather than this
example. `engine` forwards the public canonical CLI, and `collect` forwards the
canonical read-only Node collector. Work invokes the same package and collector
through authenticated connectors, with the same pin and accepted local profile.
The existing Work module exports `collectLifecycle` from the canonical package;
its historical exports are tested compatibility shims. On Provelume the trusted
PR workflow invokes `event-guard` through the same native adapter, preserving the
accepted local classifier, event binding and scope restrictions. The event guard
checks scope; it does not claim a journal operation or replace qualification.
Keep tool caches in `.agent/`; for Ruff use `--cache-dir .agent/ruff-cache` so its
nested configuration does not create extra files inside the immutable vendor tree.

Explain does not authorize writes. State-changing operations require an independently
enrolled host outside the candidate checkout, an authenticated account, existing
approved signer identity, accepted profile, exact scope and the workstream owner.
The adapter cannot generate approval, claim another owner or convert an editable
PR description into authority. Preserve raw observations and the signed journal.

Use `python tools/agent_protocol_v2.py acquire` for the source selected explicitly
by the independently accepted consumer pin. Published-release pins retain their
original five-asset acquisition and historical receipt verification. A
`CANONICAL_GIT` pin instead authenticates the canonical numeric repository,
accepted normal merge, complete commit/tree identity, ancestry and independent
OWNER receipt; the shared Core packager reconstructs five deterministic source
artifacts with the full file/mode/blob inventory. CLI and Work use this same
adapter and canonical verifier; a Work host may provide its authenticated
`fetch_source` read capability.

`acquire --offline` verifies the retained proof and every source/cache byte
without Git or network, using the independently accepted consumer pin as the
source authority. Corrupt, partial or unmanaged caches are preserved and refused.
Acquisition never changes pins or grants authority. Keep source observations and
artifacts under ignored `.agent/`; no Git or GitHub is needed by the application
runtime. An SDK publication is not a prerequisite for this explicit Git route.

Dependency qualification inventories operational test/build/vendor/platform and
native-tool surfaces as well as runtime SBOM. Record official affected/fixed
ranges and observed applicability; preserve intentional isolated compatibility
inputs. PRODUCT and PROTOCOL corrections keep separate homogeneous owners.
Partial scans do not establish general security or protected scanner closure.

For one journal use START, REFRESH, INTERRUPT, RESUME, HANDOFF, QUALIFY,
INTEGRATE, RECONCILE, RECONCILE_NOT_APPLIED, CLOSE and ABANDON through their typed
interfaces. Reobserve before each write, compare expected journal tip and candidate
head, and reconcile an uncertain operation before retrying. Never edit event files,
reset history or convert a failed gate into PASS. Production effects remain subject
to the existing local policy; a Protocol operation cannot acquire those capabilities.

The Protocol host profile is for PROTOCOL. PRODUCT follows the repository's
accepted native qualification and effect policy; do not run PRODUCT through a
PROTOCOL-only qualifier. Migration of an existing lifecycle needs its supported
owner-coordinated route. A cache is not a second lifecycle.

An accepted native PRODUCT operator binds its existing authenticated collector,
local policy/consent authority, normal merge transport and typed recovery collector
through `agent_protocol_v2.bind_product_host`. It returns the same canonical
`ProtocolHost` used by the public lifecycle operations. The binding checks the
consumer identity, operational/Work source and PRODUCT/v2 repository policy before
exposing writes. Native qualification must retain all repository-specific checks
and release/consent evidence in its NATIVE gate; the seven common gates remain
mandatory. This Python host API does not load candidate-selected modules, trust an
editable PR receipt, or infer permission from JSON. The CLI's Protocol enrollment
route is not a substitute for this local PRODUCT host binding.

After each significant milestone state what is verified, the one immediate next
action and where to execute it, then the remaining milestones. Continue authorized
work in the same session. For a genuine handoff preserve owner, journal location,
expected head, accepted pin/profile, unresolved gates and the one next action.
Record actual available model/effort only in that handoff. Unknown measurements
remain UNKNOWN. A proposed new objective does not authorize starting it.

## PR-local legacy base advancement

The historical `tools/agent_protocol.py preflight` requires the live snapshot
base to equal the original BIND base. Its refusal after main advances is expected
under that receipt's original contract. Ancestry alone does not satisfy that
identity comparison. Policy recovery 1.4.9 cannot repair this case.

The current native Provelume adapter supplies the explicit
`legacy-base-preflight` operation for this missing local continuation path.
This is consumer-specific: the historical BIND fixes `gabned/provelume` and its
PR-local coordinates. Extend the registered native adapter and its conformance,
rather than changing the frozen validator, canonical package or compatibility
corpus. This operation does not activate Lifecycle v2 or migrate authoritative state.
A candidate implementation is not authority for an active PRODUCT workstream:
qualify and integrate its separate PROTOCOL PR before ordinary use.

The original BIND, its basis, policy, effects, owner and receipts remain immutable.
The new receipt separately binds the original base and actual advanced base; it
never projects a current snapshot onto the old base or filters the historical
preflight's errors. The unchanged historical preflight is embedded with its
original refusal. This is fresh qualification, never retroactive repair or rebind.

An authenticated host first retains all raw sources and independently selects the
original BIND digest, expected head and observation digest from the same PR-local
ledger. Hashes authenticate no source themselves. Collect within 15 minutes:

- The raw repository, PR, actual main Git ref, candidate Git commit and GitHub test
  merge Git commit; the latter must have ordered parents [current base, head] and
  exactly the candidate tree.
- Every PR files page, including original rename names; retain pagination receipts
  and compare the aggregate with the PR count and complete native Git delta.
- A fresh ordinary snapshot with current policy/authority, complete exact-head CI
  and attempts/jobs, reviews/threads, native qualification and every current finding.
  Existing product and release gates remain independently mandatory.
- A freshly recomputed effect report over the entire actual base-to-head delta,
  under the original policy. Effects must equal the original prediction, and
  current capabilities must not exceed independently retained original capabilities.

The observation object has exactly `schema: provelume-base-observations/v1`,
`observed_at`, `repository`, `pr`, `default`, `candidate`, `test_merge`,
`files` (the raw aggregate) and `files_complete`. The latter summarizes retained
complete page proofs; it cannot replace authentication or missing pages.
Use a complete clean checkout of that exact PR branch. The offline adapter proves
original-base â†’ current-main â†’ candidate and binding-basis â†’ candidate ancestry,
checks all candidate/test-merge trees and ordered parents, and retains native Git
proofs. Shallow, grafted, replaced, dirty, foreign or mismatching checkouts refuse.
No Git transport, credential helper, candidate hook or fsmonitor is invoked.
Before reading worktree contents, refuse repository-local filters, configuration
includes and worktree-specific configuration, plus masking index flags, sparse
entries and gitlinks. Git subprocesses receive only the platform path, locale and
temporary-directory environment needed for these offline reads, excluding unrelated
host variables. Optional index writes and pagers are disabled.

```bash
python tools/agent_protocol_v2.py legacy-base-preflight \
  --snapshot .agent/current-snapshot.json --binding .agent/original-binding.json \
  --effects .agent/current-effects.json --observations .agent/base-observations.json \
  --repository-path /path/to/exact-clean-pr-checkout \
  --expected-head "$EXPECTED_HEAD" --binding-sha256 "$ORIGINAL_BIND_SHA256" \
  --observations-sha256 "$INDEPENDENT_OBSERVATIONS_SHA256" \
  --output .agent/new-base-preflight.json
```

The distinct `provelume-legacy-base-preflight/v1` receipt reports
`BASE_ADVANCE_PROVEN` separately from readiness. Draft, failing/unknown CI,
unresolved threads, findings, review requirements and all other ordinary gates
still block. Invalid source/identity/proof returns REFUSED (exit 2); valid identity
with blocked gates returns BLOCKED (exit 1). READY (exit 0) has no new capabilities
and does not dispatch a merge. Output uses exclusive creation and cannot overwrite
earlier evidence. Resolve and validate the destination before qualification: it
must be outside the checked source or inside its ignored `.agent/` evidence
directory, with an existing parent and no symlink/junction traversal. Git metadata,
tracked/unignored source paths and existing destinations are refused. Recheck HEAD
and cleanliness after the actual write; an observed concurrent change leaves a
BLOCKED receipt in the newly created file. Keep this receipt and its raw sources in the existing PR-local
ledger; no new checkpoint or second owner is created.

Only a fresh independently authorized action can consume a READY observation.
Refresh GitHub again at that boundary; re-run all stale dependent evidence after
head, base, runtime, workflow or policy changes. Equal trees do not transfer CI
between heads. A later main advancement needs a new observation and receipt,
retaining every earlier FAIL and receipt. Actual integration, release and
post-merge reconciliation keep their existing independent requirements.

## Review authority

The accepted local instructions and actual maintainer requests determine review
requirements. This adoption adds no unconditional Codex Code/Security requirement.
An explicit request or independently required repository review must be bound by
the host before qualification; editable JSON cannot remove it. Every current
technical finding and complete review/thread inventory remains binding. Use normal
expected-head GitHub merge and stop on a platform denial. Review unavailability
is never a clean verdict or a waiver of an actual requirement.
