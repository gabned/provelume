# Native Protocol operations

The accepted pin in `.github/agent-protocol/pin.json` selects the same immutable
Protocol source for CLI and Work. Read the canonical topic contract and the local
documents selected for the actual phase, host and workstream. A byte digest proves
integrity, never authority. The repository's PRODUCT policy, required native tests,
review governance and production consent remain local.

Run `python tools/agent_protocol_v2.py verify` before importing the dependency.
Select documentation with `python tools/agent_protocol_v2.py documents --phase
START --host CLI --workstream PROTOCOL`; use the actual context rather than this
example. `engine` forwards the public canonical CLI, and `collect` forwards the
canonical read-only Node collector. Work invokes the same package and collector
through authenticated connectors, with the same pin and accepted local profile.
The existing Work module exports `collectLifecycle` from the canonical package;
its historical exports are tested compatibility shims. On Provelume the trusted
PR workflow invokes `event-guard` through the same native adapter, preserving the
accepted local classifier, event binding and scope restrictions. The event guard
checks scope; it does not claim a journal operation or replace qualification.
Keep tool caches in `.agent/`; for Ruff use `--cache-dir .agent/ruff-cache` so its
nested configuration does not create extra files inside the immutable vendor tree.

Explain does not authorize writes. State-changing operations require an independently
enrolled host outside the candidate checkout, an authenticated account, existing
approved signer identity, accepted profile, exact scope and the workstream owner.
The adapter cannot generate approval, claim another owner or convert an editable
PR description into authority. Preserve raw observations and the signed journal.

Use `python tools/agent_protocol_v2.py acquire` to download the five public release
artifacts selected by the accepted pin. It checks their complete bytes and sizes,
the embedded source inventory, every source byte and archive mode against the
vendored installation. `acquire --offline` repeats verification using only the
ignored `.agent/protocol-artifacts/` cache. A corrupt or unmanaged cache is
preserved and refused; acquisition does not change pins, source files or authority.
Work uses the same command or adapter function, never a second source inventory.

For one journal use START, REFRESH, INTERRUPT, RESUME, HANDOFF, QUALIFY,
INTEGRATE, RECONCILE, RECONCILE_NOT_APPLIED, CLOSE and ABANDON through their typed
interfaces. Reobserve before each write, compare expected journal tip and candidate
head, and reconcile an uncertain operation before retrying. Never edit event files,
reset history or convert a failed gate into PASS. Production effects remain subject
to the existing local policy; a Protocol operation cannot acquire those capabilities.

The Protocol host profile is for PROTOCOL. PRODUCT follows the repository's
accepted native qualification and effect policy; do not run PRODUCT through a
PROTOCOL-only qualifier. Migration of an existing lifecycle needs its supported
owner-coordinated route. A cache is not a second lifecycle.

An accepted native PRODUCT operator binds its existing authenticated collector,
local policy/consent authority, normal merge transport and typed recovery collector
through `agent_protocol_v2.bind_product_host`. It returns the same canonical
`ProtocolHost` used by the public lifecycle operations. The binding checks the
consumer identity, operational/Work source and PRODUCT/v2 repository policy before
exposing writes. Native qualification must retain all repository-specific checks
and release/consent evidence in its NATIVE gate; the seven common gates remain
mandatory. This Python host API does not load candidate-selected modules, trust an
editable PR receipt, or infer permission from JSON. The CLI's Protocol enrollment
route is not a substitute for this local PRODUCT host binding.

After each significant milestone state what is verified, the one immediate next
action and where to execute it, then the remaining milestones. Continue authorized
work in the same session. For a genuine handoff preserve owner, journal location,
expected head, accepted pin/profile, unresolved gates and the one next action.
Record actual available model/effort only in that handoff. Unknown measurements
remain UNKNOWN. A proposed new objective does not authorize starting it.
